Max-effort pass over my own plan turned up one claim to correct, three genuine upgrades, and a sharper version of the boundary. Here's the delta.

**The correction (I owe you this one).** I told you interactions need "roughly 4× the n." Incomplete to the point of misleading. The interaction contrast in a 2×2 has twice the standard error of a main effect at the same total N, so: an interaction *as large as* the main effect needs ~4×; the far more common case — interaction *half* the main effect, e.g. an effect present in one stratum and muted in the other — needs ~**16×**. My v1 plan would have shipped the heuristic; the improved plan ships the exact computation (interaction powered as a proper contrast with correct df), and the 4×/16× business is demoted to educational copy explaining *why* the number is so big.

**Upgrade 1 — exact numerics with visible receipts.** v1 would have used normal approximations, which run a few units low at small n — exactly where a min-n tool matters most. Improved plan: implement noncentral t, F, and χ² distributions properly (standard numerics — incomplete beta/gamma, Poisson mixtures) so every answer is G*Power-grade, not approximation-grade. And because an instrument you can't audit is an instrument you can't trust: a **Receipts panel** ships ~25–30 reference cases from published sources (Cohen's tables, G*Power manual examples — e.g., d=0.5, α=.05 two-tailed, 80% power → 64/arm), re-run **live in the page** with pass/fail shown. The tool validates itself in front of you. I'll also verify the math engine in node against those anchors before the file ever reaches you.

**Upgrade 2 — you never pick an abstract effect size.** This is the real answer to "stats is precisely my weakness," and v1 undersold it. Every calculator gets a *derive-from-what-you-know* helper: type two predicted group means and an SD → it computes d; type two proportions → h; type your predicted **cell means** for a factorial → it derives the effect size for every main effect *and the interaction* (this is the input mode that makes the 16× problem visible instead of fatal). And the doctrine for choosing magnitudes gets stated plainly: power for the **smallest effect you'd actually care about**, not the effect you hope for — pilot data beats literature beats Cohen's benchmarks, which the tool treats as last resort, not default.

**Upgrade 3 — the test family completes, without breaking the boundary.** Turns out several things I'd deferred are closed-form cheap, so the "fully reusable" version includes: **non-inferiority and equivalence modes** on the two-arm tests (a margin field + shifted null — "no worse than" is a live question in model-comparison work); **paired proportions** (McNemar via correlation-adjusted approximation, labeled as such); a **rank-test inflation toggle** (+~5% if you'll analyze with nonparametrics, caveat included); **correlation** (Fisher z — cheap, and calibration-style questions are literally correlation questions); **omnibus χ²** so proportions get the "anything different at all?" test that means get from ANOVA; and the **cluster mode now reports clusters-per-arm**, handles unequal cluster sizes, and warns when clusters-per-arm drops below ~8, where the whole approximation regime gets shaky. Everything here is still closed-form — the boundary principle survived max scrutiny intact.

**The planner half gets operational, not just descriptive.** Define your IVs and their levels and the tool auto-generates the full cell grid — declare two IVs and it *detects the factorial* and routes the power math accordingly. A working **seeded blocked-randomization-list generator** (downloadable CSV) so the plan produces an actual allocation sequence, reproducibly. A **preregistration export**: one button yields the full design as markdown, including the auto-drafted power sentence ("To detect… with 90% power at α=.05, we require N per arm, inflated to M for 10% attrition"). **Save/load with multiple named plans** (localStorage + file export) so reusable means *actually reused*. Your unit label — participants, prompts, sessions, runs — propagates through every sentence the tool writes.

**The escape hatch gets named honestly.** The one design the closed forms genuinely cannot carry is fully **crossed random effects** — the same prompt set through every model, runs nested in both. The tool says so explicitly and points to simulation (simr/faux/Superpower) rather than pretending a formula exists. Also refused on principle, with a one-line explanation: post-hoc "observed power," which is just your p-value wearing a costume.

**Still out, same reason as before:** survival, count models, full ordinal proportional-odds, sequential alpha-spending, Bayesian assurance — each requires a data-generating story a form field would have to fake.
